# v18 改革执行宪法

> 这份文档是改革期间的最高约束。每开始一个新阶段前必须重读。
> 每完成一项改动后必须对照检查。这不是建议——是强制纪律。

---

## 三大约束（每时每刻必须遵守）

### 约束 1：不做清单外的事
每个阶段有冻结的改动清单。遇到"顺便可以修"的新发现：
- 记录到 `docs/v18/discovered_during_execution.md`
- **不在当前阶段做**
- 留到方案复审时决定归入哪个阶段

### 约束 2：先测试再改代码
每一项改动的顺序：
1. 先写测试（定义期望行为）
2. 跑测试确认它失败（验证测试有效）
3. 改代码
4. 跑测试确认通过
5. 跑全量测试确认无回归
6. 提交

### 约束 3：每项改动后"再思考一下"
每完成一项改动，问自己：
- 这项改动引入了什么新的依赖或副作用？
- 它和上一项改动有没有冲突？
- 它是否真的服务于当前阶段的设计原则？
- 如果我只做这一项改动（不做后面的），系统是否还能正常运行？

## 19 个已暴露的盲点（每阶段开始前检查相关项）

### 阶段一（修记忆）的 7 个盲点

| # | 盲点 | 应对 |
|---|------|------|
| 1 | 信息到达≠信息使用 | 每项知识闭合必须同时在 leader.md 加方法论指导 |
| 2 | 新增 key 超过 MAX_KEYS | goal_progress=tier1, causal_history/lessons=tier2, exp_value=tier3 |
| 3 | causal_history 的 verified 无验证路径 | 给全部因果链，标注 verified 状态，LLM 自己判断 |
| 4 | 结构化 metric 行与 compaction 兼容 | metric 行以 `[Cycle N]` 开头，和现有 `[timestamp]` 格式兼容；compaction 保留最新 |
| 5 | brief 目标解析（中文+非结构化） | 用正则 `(?:val_)?(\w+).*?<\s*([0-9.]+)` 提取，提取失败时 fallback 到 config |
| 6 | training_log_parser 接入后旧正则残留 | 接入时同时删除 monitor/verifier 里的旧正则，不并存 |
| 7 | model_structure_scanner 返回格式兼容 | 先验证 analyze_model 的调用者期望什么格式，scanner 按格式返回 |

### 阶段二（工具内聚安全）的 4 个盲点

| # | 盲点 | 应对 |
|---|------|------|
| 8 | workspace 路径非标准（config workspace='.'） | write_file 的路径校验基于已解析的 workspace Path，不硬编码子目录名 |
| 9 | dry-run 检查需要状态 | 用 experiment_manifest.json 的 timestamp 判断（Phase 3 已建）|
| 10 | GC 删文件的安全性 | GC 只归档不删除；有保护列表（models/datasets/scripts/PROJECT_BRIEF）|
| 11 | 工具返回 error 后 LLM 反复重试 | error 信息明确（"路径X违反规则Y，请改用Z"），不是泛化错误 |

### 阶段三（LLM 自主认知循环）的 5 个盲点

| # | 盲点 | 应对 |
|---|------|------|
| 12 | 删 enforcement 后 LLM 失控 | **前置依赖**：阶段一的记忆必须验证有效后才能删 enforcement |
| 13 | phase gate / roadmap 不全是研究决策 | phase gate 保留（安全约束）；roadmap 变成 ResearchAdvisor 的信息注入 |
| 14 | sandbox 1518 行如何变工具 | 提取 check_feasibility（前向验证）为一个工具；其余层暂不暴露 |
| 15 | prompt 删太多 LLM 失控 | 渐进式：每删一条 enforcement，先运行验证行为不退化 |
| 16 | 如何验证"去掉强制后行为没退化" | 用 mock cycle 集成测试：验证 LLM 在有记忆的情况下自主避错 |

### 阶段四（非阻塞+通用化）的 3 个盲点

| # | 盲点 | 应对 |
|---|------|------|
| 17 | 非阻塞后 GPU 被占时 THINK 能做什么 | launch_experiment 返回 GPU 占用状态；THINK 知道"GPU 忙，做分析任务"|
| 18 | 不同领域的 metric 阈值完全不同 | config `goals.metrics` 定义 key+target+direction，verifier 从 config 读 |
| 19 | 异步状态机复杂 | 先实现单实验非阻塞（同时只有 1 个在跑），验证稳定后再考虑并行 |

## 跨阶段联动（每阶段结束前检查）

```
联动 1：阶段一记忆有效 → 阶段三才能删 enforcement
  → 阶段一验收时必须确认：LLM 在有记忆时确实避免了重复错误
  → 如果记忆有效但 LLM 仍重复错误 → 阶段三不能删 enforcement，需要先加强 prompt

联动 2：阶段二工具内聚安全 → 阶段三 run() 才能去掉安全检查
  → 阶段二验收时必须确认：write_file/launch_experiment 的安全校验生效
  → 阶段三 run() 简化时，确认安全检查不再需要在 run() 层做

联动 3：阶段三插件变工具 → 阶段四非阻塞才能在训练期间调工具
  → 阶段三验收时必须确认：工具在 ToolRegistry 注册且 LLM 可调用
  → 阶段四实现非阻塞时，确认训练期间工具可正常使用

联动 4：每阶段不能破坏上一阶段的验收指标
  → 阶段二不能破坏阶段一的知识注入
  → 阶段三不能破坏阶段二的安全约束
  → 阶段四不能破坏阶段三的工具注册
```

## 每阶段的开始/结束检查清单

### 开始一个新阶段前
- [ ] 重读本宪法
- [ ] 重读本阶段的冻结清单
- [ ] 检查本阶段的盲点是否有新的理解
- [ ] 确认上一阶段的验收指标全部满足
- [ ] 确认跨阶段联动的前置条件已满足

### 完成一项改动后
- [ ] 测试通过（该项的测试 + 全量测试）
- [ ] "再思考一下"：有没有引入新的依赖/副作用？
- [ ] 改动是否只碰了允许的文件？
- [ ] 有没有发现清单外的问题？（记录，不做）

### 完成一个阶段后
- [ ] 所有验收指标满足
- [ ] 全量测试通过
- [ ] 代码量变化符合预期（升或降）
- [ ] 跨阶段联动的前置条件已为下一阶段准备好
- [ ] 运行一次真实 smoke test（如果可能）
